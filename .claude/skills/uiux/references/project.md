## Stack

- **React 18.3** + **Vite 5.4** + TypeScript 5.9 (SPA; no SSR).
- **TanStack Router 1.168**: file-based routes in `src/routes`, generated by `@tanstack/router-vite-plugin`. URL state goes through `validateSearch` + `useSearch`.
- **TanStack Query 5** for server state.
- **Styling is hybrid.** Hand-written CSS in `src/styles/*.css` does most of the work. **Tailwind 3.4** (with `tailwindcss-animate` and `@tailwindcss/typography`) serves as a utility layer, and **shadcn/ui** components sit in `components/ui` (cva + Radix: avatar, dialog, label, slot). `cn()` = clsx + tailwind-merge (`lib/utils.ts`).
- Icons come from **lucide-react**, toasts from **sonner 1.7**, and markdown from react-markdown with remark-gfm/math and rehype-katex/highlight. Collaboration uses **yjs**.
- **Package manager: npm** (`package-lock.json`). A stale `bun.lockb` also exists; don't use bun.
- Backend is FastAPI on :3000 (repo root `backend/`). Vite proxies `/api` and `/ws` to it.
- **Framework notes to obey before touching router APIs:** always pass a `select` to `useRouterState`. The one in `__root.tsx` is load-bearing for navigation performance (memory: topical-perf-router-subscriptions).

## Design tokens — `src/styles/tokens.css`

Theming: `:root` holds the light values and `:root[data-theme='dark']` overrides them. The theme is set before first paint by a script in `index.html`; `lib/theme.ts` handles `setTheme` (view-transition wipe) and `useTheme`. Preference is `light | dark | system`, stored in `localStorage.topical_theme`. **Parity check (2026-09-30): every colour token exists in both themes.** Non-colour tokens (type, radius, motion, control height, gutter) are theme-invariant by design.

## Design language (read-back)

- **Refined paper.** Warm cream ground, white sheet cards on 1px hairlines with barely-there shadows. The dark theme is the same paper under warm charcoal light.
- **One saturated hue:** terracotta = "actionable". Indigo appears only for LaTeX. Danger is rose.
- **Type:** Newsreader serif for display and reading (600, about -0.015em, `opsz` auto); IBM Plex Sans for UI; Plex Mono for code. The ramp runs from `--text-xs` to `--text-display` with no gaps.
- **Edges:** one radius ramp. Controls use 9px, cards 14px, dialogs 18px; pills are for descriptive chips only. Three control tiers only: primary (flat terracotta), secondary (paper + hairline), ghost (chrome only on hover; all icon-only controls).
- **Motion:** transitions only, ease-out, 110–300ms tokens. Press is `scale()` (0.97 filled, 0.94 ghost, 0.994 cards). No stagger on app data grids. Glass only on floating chrome.
- **"Bold" here means** display serif at `--text-display` against small UI labels, the single terracotta primary, and flat paper. It is never washes, gradients or glass on cards.

**Deviations from the dominant language (audit input):**
- Two parallel button systems. The shadcn `Button` (cva, Tailwind colours) coexists with 13 aliased CSS button classes in `styles/buttons.css`, and the icon-button look has 8 aliases.
- Two avatar implementations (`ui/avatar.tsx` Radix vs `Avatar` in `primitives.tsx`), plus a hand-rolled `.nav-avatar` in the shell.
- Modals: Radix `Dialog` for centred dialogs, and `Modal` (Radix behaviour, caller-owned scrim and panel) for sheets, the ⌘K palette and the mobile menu. Never hand-roll a fixed overlay.
- Arbitrary Tailwind values (`text-[13px]`, `text-[11.5px]`, `text-[var(--ink-muted)]`) and inline `style={{…}}` in pages and in primitives themselves (`EmptyState`, `DocTypeIcon`, the nav in `__root.tsx`).
- The Toaster is styled via inline `toastOptions.style` in `__root.tsx`.

## Global behaviours

- **Focus:** there's a global `:focus-visible { outline: 2px solid var(--accent-400); outline-offset: 2px }` in `tokens.css`. `outline: none` appears 13× in `<STYLES>`; each one needs a replacement ring (for example, `.glass-input:focus` uses a 3px `--accent-soft` box-shadow).
- **Reduced motion:** a global block in `tokens.css` narrows `transition-property` to non-travelling properties at 140ms and stops animations. `setTheme` skips the wipe when motion is reduced. "Reduced, not none" is deliberate.
- **Target floor:** `button { min-height: 2.5rem; min-width: 2.5rem }` in the base layer. **Any small control must declare an explicit height, or it inflates to 40px.**
- **Overflow is not masked:** `body` has no `overflow-x: hidden` (removed; it once hid a clipped 360px layout). The landing root clips its own hero art. A page that overflows scrolls, and the harness flags it via `scrollWidth`.
- Full-height shells use `dvh` (fixed 2026-09-30, TK-08).
- **No route-level error or 404 UI.** No `notFoundComponent`/`errorComponent` exists anywhere, and `_authenticated.tsx` hand-rolls its loading/signed-out states.

## Standing rules (quoted, with source)

From project memory (Claude Code's per-project memory directory):
- *topical-claude-ui*: "**Three control tiers, no fourth:** primary (flat terracotta), secondary (white paper + hairline), ghost (no chrome until hover; all icon-only controls)." The tiers still stand. The second half of that note ("page files keep owning size") is **superseded** by the primitives doctrine: `Button`/`IconButton` own their sizes, and page files may only place them.
- *topical-claude-ui*: "rounded rectangles act, pills describe — controls take the ramp, chips/badges stay pills."
- *topical-claude-ui*: "**Glass goes on chrome that floats over moving content. Nothing else.**" … "Glass is never nested." "Don't put `.editor-menu` back in glass.css's lists."
- *topical-claude-ui*: "**Never write a palette colour as a literal** — use `rgb(var(--x-rgb) / a)`." "Deleting a token silently kills the whole `box-shadow` that used it."
- *topical-claude-ui*: "`--accent-ink` must flip by theme." "Accent text on an `--accent-soft` fill needs `--accent-600`." "`--accent-200`/`-300` are fills only, never text."

- *topical-motion-rules*: "**`transition: all` is banned.**" "Press is `transform: scale()`, not `translateY(1px)`." "Popovers are origin-aware, modals are not." "Reduced motion is 'reduced', not 'none'." "No stagger on app data grids." "no `ease-in` curve."
